# Jailbreak Vaccine: Benchmark Inference

Inference implementation for **Jailbreak Vaccine: A Semantically Preserving Internal Defense Against Harmful Content Generated by Diffusion Models**. The supplied artifact covers the SD1.4 setting. It generates one image per CSV row for exactly these five
tasks by default:

| Task | CSV in `data/` | Prompt column | Rows in the supplied files |
| --- | --- | --- | --- |
| `sneakyprompt_meaningful_perturbed` | `SneakyPrompt200_meaningful_seeded_123.csv` | `perturbed_text` | 200 |
| `sneakyprompt_nonsense_perturbed` | `SneakyPrompt200_nonsense_seeded_1234.csv` | `perturbed_text` | 200 |
| `nudity_eta_3_k_77` | `Nudity_eta_3_K_77.csv` | `prompt` | 95 |
| `p4dn_16_prompt` | `p4dn_16_prompt.csv` | `prompt` | 151 |
| `clean` | `clean.csv` | `prompt` | 100 |

These tasks correspond to the paper's **SP-M, SP-N, RAB, P4D, and SixCD**, respectively. The released LoRA contains only the best validation-safety selection; other saved checkpoint selections are not distributed.

The supplied files contain **746 rows in total**. Task names containing numbers
are identifiers; the program reads the actual CSV rows without assuming that
those numbers are dataset sizes. No additional task is run by `--tasks all`.
Dataset CSVs and model weights are external inputs and are not bundled here.

## Directory layout

```text
project/
├── code_github_eval/
│   ├── infer.py                 # command-line entry point
│   ├── inference_config.py      # tasks, paths, seeds, and input checks
│   ├── inference.py             # pipeline/LoRA loading and image generation
│   ├── run_inference.sh         # optional Bash launcher
│   ├── requirements.txt
│   └── tests/
├── data/
│   └── ...                     # the five CSVs listed above
├── models/
│   └── stable-diffusion-v1-4/
└── output/
    ├── safety_lora/
    │   └── best_val_loss_safety_lora/
    │       └── pytorch_lora_weights.safetensors
    └── generated_benchmarks/    # created during inference
```

The default project root is the **parent of this code directory**, independent
of the terminal's working directory. All relative command-line paths are
anchored at `--project_root`. If the contents of this directory become the root
of a standalone repository, put `data/` and `models/` there and pass
`--project_root .`.

The default adapter is the supplied paper checkpoint at
`checkpoints/safety_lora/best_val_loss_safety_lora/pytorch_lora_weights.safetensors`.
If absent, the best-safety checkpoint from the accompanying training package at
`output/safety_lora/best_val_loss_safety_lora/pytorch_lora_weights.safetensors`
is used. Otherwise, the code searches `output/` for a **unique** checkpoint with the same
`best_val_loss_safety_lora/pytorch_lora_weights.safetensors` suffix. Multiple
matches require an explicit `--lora_path`; a checkpoint is never selected by
modification time. Other checkpoint types, such as `final_lora`, must be
selected explicitly. No adapter files are copied or moved automatically.

## Installation

Use Python 3.10 or 3.11 in a separate environment. Install a matching PyTorch
and torchvision build for the target CUDA system, then:

```bash
python -m pip install -r code_github_eval/requirements.txt
```

The requirements use the same candidate dependency ranges as the training
package. They are not a recovered lockfile from the original experiment or a
GPU-validated environment. xFormers is optional and only needed when requested.

The base model must be a **local Diffusers model directory** with
`tokenizer/`, `text_encoder/`, `unet/`, `vae/`, and `scheduler/`. Both complete
pipelines with `model_index.json` and manually assembled component directories
are supported. Standard safetensors or `.bin` weights are accepted. A
pipeline-wide fp16 variant is used only when all three model components have
fp16 safetensors; otherwise standard weights are loaded at the requested dtype.
Hub IDs and automatic downloads are not used. `HF_HOME`, if set, is respected;
otherwise the cache location is `<project_root>/.cache/huggingface`.

## Check and run

Run these commands from `project/` (PowerShell or Bash):

```bash
python code_github_eval/infer.py --help
python code_github_eval/infer.py --dry_run
python code_github_eval/infer.py --check_only
python code_github_eval/infer.py
```

`--check_only` inspects the selected CSVs, model filenames, scheduler config,
LoRA file, and existing output metadata without importing the training/inference
libraries or creating outputs. It does not load model tensors or validate GPU
execution. `--dry_run` only prints the resolved configuration.

On Linux, the launcher uses the active Python environment:

```bash
bash code_github_eval/run_inference.sh
CUDA_ID=1 bash code_github_eval/run_inference.sh
```

Use `PYTHON_BIN` for a different Python executable. No server-specific Conda
installation, user home directory, or GPU index is hardcoded.

Examples:

```bash
# Select a subset of tasks.
python code_github_eval/infer.py --tasks sneakyprompt_meaningful_perturbed,clean

# Select another checkpoint file or a directory containing the default LoRA filename.
python code_github_eval/infer.py --lora_path output/safety_lora/final_lora --model_alias final_lora

# Run the base SD model without an adapter in a separate output directory.
python code_github_eval/infer.py --no_lora

# Use a local SD2.1 base model with its matching SD2.1 LoRA.
python code_github_eval/infer.py --base_model_path models/stable-diffusion-2-1-base --lora_path models/sd21_lora/pytorch_lora_weights.safetensors --model_alias sd21_lora

# Generate at most two rows per task as a short execution smoke test.
python code_github_eval/infer.py --max_prompts 2 --batch_size 1 --output_root output/inference_smoke_test
```

Each invocation uses one selected model/adapter. Run additional adapters with
different `--model_alias` values. The original machine-specific lists of
ablation checkpoints are not required by this package.

## Generation protocol

- Inference steps: **50**; classifier-free guidance: **7.5**.
- Batch size: **4**; output image size: **512 × 512**.
- Seed for each row: **12345 + zero-based row index**, reset for each task.
- The case identifier uses `case_number`, `case`, `id`, or `ID`, in that order;
  otherwise it uses the one-based row index.
- Seeds are assigned before existing files are skipped, preserving row-to-seed
  alignment across interrupted runs. `--max_prompts` selects an initial prefix
  without renumbering rows.
- The scheduler comes from the base model's configuration, matching the
  supplied inference code. The local SD1.4 checkpoint specifies `PNDMScheduler`.
- The final pipeline safety checker is **disabled**, matching the supplied
  evaluation protocol. The code saves the pipeline's generated images directly.
- Precision defaults to fp16 on CUDA and fp32 on CPU. Override with
  `--precision`; CPU execution requires `auto` or `fp32`.

Task selection, custom paths, dimensions, batch size, seeds, precision, and
inference steps are exposed through `--help`. The code rejects missing or
empty prompt fields instead of silently changing CSV row indices.

## Outputs and interrupted runs

```text
output/generated_benchmarks/
└── safety_lora/                 # --model_alias (base for --no_lora)
    └── <task_name>/
        ├── 0000_case<id>_seed12345.png
        ├── ...
        ├── prompts.csv
        └── generation_config.json
```

`prompts.csv` records the rows requested in that invocation, including prompt
text, case ID, row index, seed, and image filename. `generation_config.json`
records the input paths relative to the project, the CSV/LoRA SHA-256 hashes,
and generation settings. External paths are reduced to their basename to avoid
embedding a local user's home directory in the metadata.

Existing images are skipped by default. Use `--no-skip_existing` to regenerate
images with the same recorded configuration. If a selected task directory has
different metadata, or has untracked files without a configuration, the run
stops; choose a new `--output_root` or `--model_alias`. This prevents mixing
outputs from different adapters, prompt files, or sampling settings. PNG files
are written through temporary files and renamed after saving.

This package generates images and provenance records; it does not compute
safety or image-quality metrics. Model loading and GPU image generation have
not been validated in the preparation environment, which lacks PyTorch and
Diffusers. The tests use a simulated pipeline to verify control flow and file
handling without claiming to validate diffusion outputs.

## Lightweight verification

```bash
python -B -m unittest discover -s code_github_eval/tests -v
```

Tests cover the five-task mapping, portable paths, checkpoint selection,
seed/index preservation, output protection, partial fp16 variants, and
generation batching, saving, and resumption. All Python source and shell files
use LF line endings. The `.gitignore` excludes data, weights, caches, and
generated artifacts.
