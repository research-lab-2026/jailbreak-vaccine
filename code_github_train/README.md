# Jailbreak Vaccine: LoRA Training

Training implementation for **Jailbreak Vaccine: A Semantically Preserving Internal Defense Against Harmful Content Generated by Diffusion Models**. The supplied preset targets Stable Diffusion v1.4. Training starts
from the base UNet and initializes a new adapter. The frozen base UNet supplies
the denoising trajectory; only the LoRA parameters are optimized.

## Directory layout

The default project root is the **parent of this code directory**, independent
of the terminal's working directory:

```text
project/
├── code_github_train/
│   ├── train.py                 # portable entry point
│   ├── training_config.py       # arguments, paths, and input checks
│   ├── training.py              # training, losses, validation, checkpoints
│   ├── run_train.sh             # optional Bash launcher
│   └── requirements.txt
├── data/
│   └── I2P_sexual_931.csv
├── models/
│   ├── stable-diffusion-v1-4/
│   ├── stable-diffusion-safety-checker/
│   ├── clip_noise_finetuned_safety_checker/
│   │   └── best/
│   └── clip-vit-large-patch14/
└── output/
    └── safety_lora/             # created during training
```

The dataset and model weights are external inputs, not bundled with this code.
The CSV must contain a `perturbed_text` column with at least 10 usable prompts;
use `--prompt_column` for another column. The default run uses the full supplied
CSV, with no prompt limit.

The SD checkpoint must use the Diffusers directory format with `tokenizer/`,
`text_encoder/`, `unet/`, `vae/`, and `scheduler/`. The two safety checker
directories must be loadable as `StableDiffusionSafetyChecker`; the CLIP
directory must contain the CLIP model and tokenizer. Both `model.safetensors`
and `pytorch_model.bin` checkpoint formats are accepted. Diffusers UNet/VAE
weights use the corresponding `diffusion_pytorch_model` filenames.

The finetuned safety checker is an **input checkpoint** used by the auxiliary
loss. Its own finetuning procedure is not included in this training package.
Reproducing the default experiment requires this checkpoint as well as the
specified prompt CSV and the other three models.

## Installation

Use Python 3.10 or 3.11 in a separate environment. Install a CUDA-enabled PyTorch
and matching torchvision build for the target machine, then install:

```bash
python -m pip install -r code_github_train/requirements.txt
```

The dependency ranges describe a candidate environment, not the recovered
versions of the original experiment or a GPU-tested lockfile. The code uses
Diffusers' PEFT adapter and LoRA serialization APIs, as in the
[official LoRA training guide](https://huggingface.co/docs/diffusers/training/lora).
PyTorch 2.6 or later is required by this package for `.bin` loading; the code
keeps Transformers' checkpoint loading checks enabled. xFormers is optional
and only needed when `--enable_xformers` is requested.

## Check and run

Run these commands from `project/` (PowerShell or Bash):

```bash
# Show all options without importing the training libraries.
python code_github_train/train.py --help

# Print resolved paths and hyperparameters; creates no files.
python code_github_train/train.py --dry_run

# Inspect the local CSV, checkpoint filenames, and output directory.
python code_github_train/train.py --check_only

# Start the default training experiment.
python code_github_train/train.py
```

On Linux, the optional launcher uses the active environment:

```bash
bash code_github_train/run_train.sh
CUDA_ID=1 bash code_github_train/run_train.sh
```

Select another Python executable with `PYTHON_BIN`. No Conda installation path,
user home directory, or machine-specific cache path is assumed. The default
Hugging Face cache is `<project_root>/.cache/huggingface`; an existing `HF_HOME`
environment variable takes precedence.

Relative dataset, model, output, and TensorBoard paths are resolved against
`--project_root`. If this code directory itself becomes a repository root,
place `data/` and `models/` inside it and run `python train.py --project_root .`.
For other layouts, pass the root explicitly:

```bash
python code_github_train/train.py --project_root /path/to/project --check_only
python code_github_train/train.py --output_dir output/experiment_02
```

Local loading is the default for all models. Hub model IDs are also supported:
pass an ID to the corresponding `--*_model_id` or `--*_checker_id` option and
add `--no-local_files_only` to permit downloads of SD/checker assets, or
`--no-clip_local_files_only` for CLIP. Prefix a local custom path with `./`
to distinguish it from a Hub ID; `hf://organization/model` explicitly denotes
a Hub ID. `--check_only` defers validation of Hub IDs until model loading.

An existing, nonempty output directory is rejected, for both launch methods.
Choose a new `--output_dir` for another run. This package starts a new adapter;
it does not resume optimizer state from a previous run.

## Default experiment

The preset preserves the supplied training launch settings:

| Setting | Value |
| --- | --- |
| Optimizer updates | 6000 |
| Micro-batch / accumulation / effective batch | 2 / 16 / 32 |
| Resolution | 512 |
| LoRA rank / alpha | 16 / 16 |
| LoRA targets | `to_q,to_k,to_v,to_out.0` |
| Optimizer / learning rate | AdamW / `1e-5` |
| Train / validation / test | 0.7 / 0.2 / 0.1 |
| Training seed / split seed | 42 / 42 |
| Denoising steps / CFG | 50 / 7.5 |
| Sampled denoising index range | 20–50 inclusive (ratios 0.40–1.00) |
| Prompt CLIP start ratio | 0.70 |
| Safety mode | `absolute_predx0_plus_after_delta` |
| After-latent delta weight | 0.0 to 0.5, linear in sampled denoising index |
| Safety / prompt CLIP weights | 3.0 / 0.06 |
| TV / variance / noise-delta weights | 0.0008 / 0.035 / 0.008 |
| Minimum image variance | 0.015 |
| Phrase trend weight / threshold | 1.0 / 0.18 |
| Special-care adjustment | 0.005 |
| Precision | fp16 |
| Validation | step 1 and every 100 updates, up to 186 prompts |
| Fixed validation seed | 20260723 |
| Checkpoint / log intervals | 300 / 10 updates (also log step 1) |

The objective combines absolute safety trend on the predicted clean image,
an after-latent safety delta computed with the finetuned checker, prompt CLIP
alignment, total variation, a variance floor, and weak noise regularization.
The eight phrase embeddings, loss formulas, fixed validation RNG handling,
gradient accumulation, and checkpoint selection follow the supplied code.
Boolean defaults can be disabled with their `--no-...` option, for example
`--no-use_tensorboard`.

For a short **GPU execution smoke test**, which does not reproduce the full run:

```bash
python code_github_train/train.py --max_train_steps 1 --max_prompts 10 --train_batch_size 1 --gradient_accumulation_steps 1 --val_max_prompts 1 --no-use_tensorboard --output_dir output/smoke_test
```

GPU memory and execution time depend on the hardware and model files. No full
GPU training run has been validated as part of preparing this package.
CPU execution requires `--device cpu --mixed_precision no` and is much slower.

## Outputs

Training writes `training_config.json`, prompt split CSVs, `training_log.csv`,
`validation_log.csv`, and optional TensorBoard events under the output directory
(override events with `--tensorboard_log_dir`). It saves:

- `checkpoint_step_XXXXXX/`: periodic **adapter weights only**.
- `best_val_loss_total_lora/`: best total validation objective.
- `best_val_loss_safety_lora/`: best safety validation objective.
- `best_val_score_balanced_lora/`: best mean of total and safety objectives.
- `best_val_lora/`: alias of the total-objective selection.
- `final_lora/` and the output directory root: final adapter weights.

The held-out test split is exported but is not used for optimization or model
selection. These checkpoints contain neither a full SD model nor optimizer
state. The `.gitignore` excludes datasets, weights, caches, and generated logs.

## Lightweight verification

```bash
python -m unittest discover -s code_github_train/tests -v
```

These tests cover portable paths, preset configuration, local asset checks,
split edge cases, and existing output protection without loading the models.
